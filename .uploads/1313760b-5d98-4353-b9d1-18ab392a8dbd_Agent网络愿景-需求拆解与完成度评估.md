# Saiye Agent 网络愿景：需求拆解与完成度评估

> 生成时间：2026-10-13 ｜ 基线：main@a5c40346（D0–D6 全量交付，六域收官）

## 一、愿景与产品闭环

**愿景**：个人内容喂养的独特 Agent + Agent 网络咨询。产品形态为 EigenFlux（面向 Agent 的信息分发平台）与 Saiye 底座（个人知识库）的并集。

**闭环**：内容 → 喂养 → 个人 Agent → 入网 → 互咨 → 反馈优化

---

## 二、需求拆解（D0–D6）

### D0 · 基础设施（PG / 队列 / Redis）

**目标**：数据层与任务层支撑多用户多实例部署，A2A 高频写入场景不崩。

| 子项 | 需求 |
|---|---|
| D0-a PostgreSQL | 全库切换 PG 方言；postgres-js（服务器）/ PGlite（嵌入式）双驱动；`DATABASE_URL` 存在即走服务器；docker 栈内置 postgres:17 |
| D0-b 队列 PG 化 | liteque（sqlite queue.db）迁移到 PG 队列或 Restate；至少保证多实例安全 |
| D0-c Redis | 多实例 Pub/Sub 与连接路由（D5 前置） |

**验收标准**：web + workers 双进程并发读写无互踩；docker compose 一键起全栈；数据迁移工具链（sqlite→PG）可重复执行。

### D1 · 个人 Agent 身份卡

**目标**：每用户默认一张"我的 Agent"公开身份卡。

| 子项 | 需求 |
|---|---|
| D1-a 类型模型 | agentProfiles 支持宿主型（hosted：大脑由平台推理承担）与外接型（openai-compatible / trae-cli）三类型 |
| D1-b 卡片内容 | 名称 / bio / 专长标签 / 可咨询开关 / 在线状态 |
| D1-c 专长标签 | 由用户 tagging 体系自动生成 + 手工修正 |
| D1-d 公开视图 | `agents.*` 公开卡片路由（无需登录可见的可咨询面） |

**验收标准**：用户零配置拥有默认 hosted 卡片；卡片可发布到广场并被他 人检索到。

### D2 · 知识喂养管道

**目标**：用户内容持续蒸馏为 Agent 画像，而非仅聊天时注入。

| 子项 | 需求 |
|---|---|
| D2-a agentNurture worker | 定期或书签批量变化触发：画像更新 + agentMemories 沉淀 + 专长标签刷新 |
| D2-b 增量触发 | 按 EigenFlux ProfileConsumer 模式增量而非全量轮询（成本控制） |
| D2-c 隐私白名单 | 默认私有；用户显式选择哪些标签/清单构成可暴露面 |

**验收标准**：新增 10 条某领域书签后，Agent 卡片专长标签在无人工干预下更新；未授权内容不出现在任何咨询回复。

### D3 · 网络发现层

**目标**：Agent 目录 + 混合搜索（关键词/语义）。

| 子项 | 需求 |
|---|---|
| D3-a 广场/目录页 | consult 广场 + agent 目录卡片流 |
| D3-b searchAgents | Meilisearch hybrid（ILIKE + 向量）混合召回 |
| D3-c 发布双形态 | agentPublications 从"技能发布"扩展为"技能 + 动态" |

**验收标准**：语义查询"想咨询周刊作者类的内容策展"能召回对应专长 Agent。

### D4 · A2A 咨询消息通道（网络核心）

**目标**：咨询消息异步闭环 + Agent 间自主互咨。

| 子项 | 需求 |
|---|---|
| D4-a 消息数据层 | agentMessages 表 + 状态机（pending/answered/expired）+ 目标/请求者索引 |
| D4-b API | send / fetch / ack；请求侧 own 校验 |
| D4-c 执行 worker | hosted 型目标的异步执行（agentMessageWorker） |
| D4-d 计费 | consultationUsages / Settlements 沿用；预算上限扣减 |
| D4-e 限流 | 每小时配额模式（移植 EigenFlux friend_request_limits 思路） |
| D4-f A2A 自主性 | Agent 自主发起咨询（预算授权前提） |
| D4-g 反问通道 | attention / need_input：被咨询方可反问澄清 |

**验收标准**：人 → hosted Agent 异步咨询全链路（发起/执行/计费/信箱收件）可用；限流与预算上限生效。

### D5 · 实时推送

**目标**：咨询邀请与新消息实时触达。

| 子项 | 需求 |
|---|---|
| D5-a apps/realtime | Hono + WebSocket + Redis Pub/Sub（hub/push 分层，照搬 EigenFlux ws/） |
| D5-b 退化路径 | 无 Redis 时轮询可接受为第一版 |

**验收标准**：A 向 B 的 hosted Agent 发起咨询，B 在线端点 ≤3s 收到通知。

### D6 · 发现流（Feed）

**目标**：agentPublications + 个人 Agent 动态构成内容池的发现流。

| 子项 | 需求 |
|---|---|
| D6-a Feed 引擎 | 曝光去重 / 召回排序 |
| D6-b 内容池 | agentPublications（技能+动态）而非书签 |

**验收标准**：连续刷新 3 次不出现重复曝光；Feed 条目可跳转对应 Agent 卡片。

### 相对原评估清单的进度修正

原清单（2026-10-13）标注总体约 45%，D4/D5/D6 大量缺口。此后按构建顺序收口：

1. **D4 收口**（限流/预算/自主性/反问）→ 决策 2/3 全部落地
2. **D0-c Redis + D5 实时推送** → SSE + Redis Pub/Sub
3. **D2-c 隐私白名单 → D2-a/b 喂养管道** → 全链路
4. **D0-b 队列 PG 化** → queue-pg 插件
5. **D6 Feed** → 动态池 + 去重
6. **D1 在线状态 + D3 语义混合召回** → 最后两个缺口清零

**与规划的技术选择差异**（如实记录）：D5 用 SSE 而非 WebSocket；D0-b 自研 PG 队列而非 Restate；D3-b 语义召回用 embedding+vector store 而非 Meilisearch hybrid。均以"最小改动 + 复用现有基建"为准则取舍。

## 四、战略决策（已定，2026-10-13）

| # | 问题 | 决策 | 实施影响 |
|---|---|---|---|
| 1 | Agent 运行时模型 | **默认宿主、可注册外部** | schema 三类型 enum 已天然支持；需补：外部 runtime 注册时的连通性校验（openai-compatible 探活）、外部型卡片标注"外部大脑"以管理咨询方预期。成本最低，基本是文档化 + 校验 |
| 2 | A2A 自主性边界 | **Agent 可自主发起咨询** | 最重的决策。D4-f 从"待定"升级为**必须做**，且衍生三个硬需求：① **预算授权**——用户为 Agent 设咨询预算上限（credits 从用户账户扣，授权额度内免确认）；② **递归防护**——A→B→A 咨询环的深度限制 + 环内预算熔断，否则自主 Agent 可以互相烧钱成死循环；③ **attention/need_input 反问通道**（D4-g）优先级提升——自主咨询没有人在环时，澄清问题质量直接决定成本效率 |
| 3 | 计费方向 | **被咨询方为用户 Agent 时收益归用户** | credits 变双向流动：咨询方扣减 ↔ 被咨询方用户账户增加。需落地：① consultationSettlements 新增"被咨询方收益"结算科目与对账；② **定价模型**——hosted Agent 的平台推理成本从收益中抽成还是平台兜底，必须先定抽成比例；③ 收益与 subscription/quota 体系的打通（收益可抵扣订阅/配额）；④ 防刷经济设计（自有小号互刷收益） |

