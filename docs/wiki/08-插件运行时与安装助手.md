# 08 插件运行时与安装助手

本文覆盖两个较小的 crate：`app/flowix-plugin-runtime/`（声明式插件契约）与 `app/flowix-installer-helper/`（Windows 安装预检）。

## 1. flowix-plugin-runtime

> 定位："Flowix plugin artifact contracts and non-agent execution runtime"。
> **核心原则：插件是 data-only 的声明**——只声明 UI 与输出格式，不能执行任意代码；产物由 Host 校验后写入。

### 1.1 模块

| 文件 | 职责 |
| --- | --- |
| `src/manifest.rs` | `PluginManifest` 数据模型（schema v1/v2）、`validate_manifest` 全量校验 |
| `src/lib.rs` | 内置 mindmap/webpage 工具、第三方插件发现与完整性校验、输入解析器、产物写入与序列化 |

### 1.2 清单契约（manifest.rs）

```rust
pub struct PluginManifest { /* id, name, version, schemaVersion, engines,
                               permissions, renderer, format, parser, integrity, ... */ }

pub enum PluginParser { Markdown, Json, Text, Html, MindmapMarkdown }  // 5 种

pub fn validate_manifest(m: &PluginManifest) -> Result<PluginDefinition, String>
```

校验要点：

- `permissions` 白名单：`agent.invoke | notebook.read | artifact.write`（仅安装前提示，不是授权记录）；
- `engines` semver 校验（宿主版本兼容）；
- `parser` 与 `format` 组合必须已知（未知组合安装前拒绝）；
- `integrity.files` 提供逐文件 SHA-256 校验，SKILL/integrity 路径 canonicalize 后必须仍在插件目录内且非符号链接。

schema 参考：`docs/plugin-manifest-v2.schema.json`；开发指南：`docs/PLUGIN-DEVELOPMENT.md`；示例：`examples/plain-report/`。

### 1.3 内置与第三方工具（lib.rs）

| 函数 | 说明 |
| --- | --- |
| `builtin_tools()` | 内置 `mindmap`、`webpage`（manifest/SKILL 常量即单一定义源，桌面端每次启动对账迁移） |
| `installed_tools(config_dir)` | 扫描 `~/.flowix/plugin/<id>/plugin.json`；坏插件忽略 |
| `plugin_is_enabled(config_dir, id)` | 查 `plugin/state.json` 的 disabled 集合 |

### 1.4 输入解析器

| 函数 | 约束 |
| --- | --- |
| `parse_mindmap_input(raw)` | 恰好一个一级标题且必须在首行；≤200KB；禁止 code fence |
| `parse_webpage_input(raw)` | doctype/html/head/body/title 结构；≤1MB |
| `parse_agent_artifact(parser, raw)` | 宽松模式：允许前后解释文本与单个 fence（Agent 输出防脆弱） |

### 1.5 产物创建流程

```rust
pub fn create_artifact(memo_file: &MemoFile, request: CreateArtifactRequest) -> Result<CreatedPluginArtifact, String>
```

流程：**校验输入 → 写产物文件 → 刷新索引**（无任意代码执行）。

- mindmap → `<notebook>/Mindmaps/YYYYMMDD-HHMMSS-title-uuid8.md`（普通可索引文档，frontmatter 带 `flowix_plugin: {id, version}`）；
- 其他插件 → `<notebook>/Plugins/<plugin_id>/...md`，YAML frontmatter：`flowix_plugin / flowix_renderer / flowix_format / plugin_version / agent_type / created_at / source_note`；
- 返回 `CreatedPluginArtifact{ok, action, pluginId, notebookId, title, renderer, artifactPath, notePath, ...}`。

### 1.6 桌面侧运行链（配合 04 篇第 7 节）

```
plugin_prepare_prompt（SKILL 指令 + 输出契约 + 上下文 + 用户请求 → 大提示词）
→ 交给所选 Agent runtime 执行（start_plugin_chat）
→ parse_plugin_output（markdown/json/html/mindmap-markdown 四种 parser 清洗）
→ write_output 写入笔记本 + mark_self_write_for 抑制 watcher 回声
→ 事件 plugin-run{started/completed/failed}
```

## 2. flowix-installer-helper

> Windows 专用小工具，被 NSIS 安装器（`app/flowix-desktop/nsis/flowix-cli-path.nsh`）在覆盖安装/卸载前调用。

### 2.1 职责

| 函数 | 位置 | 说明 |
| --- | --- | --- |
| `close_target_executable(target, timeout, interval, log)` | `src/lib.rs:31` | Toolhelp 快照枚举进程 → 比对完整镜像路径 → TerminateProcess + 等待 → `can_replace_file` 探测 |
| `prepare_install(root, main_executable, ...)` | `src/preflight.rs:54` | 通过命名事件 `Local\Flowix.Maintenance.Exit.{pid}` 请桌面端优雅退出；只终止产品自有 exe；`locking_processes` 用 Restart Manager 报告占用者 |
| `listen_for_shutdown(request_exit)` | `src/preflight.rs:30` | **桌面端进程内调用**：监听上述命名事件（与 bootstrap.rs 集成） |

### 2.2 CLI 参数与退出码

`--mode prepare|close-cli`、`--target`、`--main-executable`、`--error-file`（UTF-16LE 错误文件供 NSIS 读取，避免 codepage 损失）。

| 退出码 | 含义 |
| --- | --- |
| 20 | CLI 仍在运行 |
| 21 | 权限拒绝 |
| 22 | 文件被占用 |
| 23 | 文件访问错误 |
| 24 | 枚举失败 |

非 Windows 平台：仅保留错误路径（`Enumeration` 错误）。测试：`tests/lifecycle.rs`（Windows-only，复制自身作为 fixture 进程）。

## 3. 依赖关系

```
flowix-plugin-runtime ──> flowix-core（MemoFile 产物写入）＋ serde_yaml/semver/sha2/uuid
flowix-installer-helper（独立：dunce + windows crate；无内部依赖）
flowix-desktop ──> 两者（插件常量/序列化；Windows 下 listen_for_shutdown）
flowix-cli ──> flowix-plugin-runtime（plugin 子命令）
```
