# 12 测试与质量保障

## 1. 三语言测试布局

| 语言 | 运行器 | 入口 | 位置 |
| --- | --- | --- | --- |
| TypeScript（前端） | Vitest 4 + jsdom | `npm test`（vitest.run） | `app/flowix-web/**/*.test.{ts,tsx}`（约 200+ 个，与源码同目录 co-located） |
| Rust | cargo test | `npm run test:rust`（= `cargo test --manifest-path app/Cargo.toml --workspace --lib`） | 各 crate `#[cfg(test)]` + `tests/` |
| Node（DSH） | Vitest（node env）+ node --test + smoke 脚本 | dsh-appserver `npm test` / `npm run test:*`；根 `npm run test:dsh:packaging` | `dsh-appserver/test/`、`scripts/dsh-native-deps.test.mjs` |

### 1.1 前端测试要点

- `vitest.setup.ts`：预载 en-US i18n、`IS_REACT_ACT_ENVIRONMENT`、stub jsdom 缺失的 matchMedia/ResizeObserver/scrollTo。
- 重点覆盖：app/ 协调层（startup/memo-event-handler/user-config-sync/agent-window-effects 集成）、lib 纯函数（dedup/tag-path/safe-link/input-method/agent-access-defaults 等）。
- 偏单元/纯函数测试；涉及 Tauri invoke 的用 vi.mock（因此层级检查豁免测试文件）。

### 1.2 Rust 测试要点

| crate | 测试 |
| --- | --- |
| flowix-core | 大量内嵌单元测试（ops/索引/并发 RMW）；`tests/notebook_creation_performance.rs`（revision CAS、笔记本隔离、创建基准） |
| flowix-cli | `cli_smoke.rs`（二进制冒烟/JSON 错误形状/Windows stdin）；`locking.rs`（**真实 CLI 子进程**跨进程锁：并行写/结构锁等待/持有者异常退出）；`mcp_e2e.rs`（MCP 子进程端到端） |
| flowix-sync | store/v2_tests、manager/lifecycle/tests（会话恢复/退避） |
| flowix-installer-helper | `tests/lifecycle.rs`（Windows-only，复制自身作 fixture） |
| CI 策略 | 只跑 `--lib`；DSH/Wry 等环境敏感集成测试刻意排除在门禁外 |

### 1.3 DSH 测试三层

1. Vitest：protocol（InMemoryHarnessAdapter 端到端）、projector（投影/配额错误归类）、各服务、long-session（HistoryGuard/缓存有界/万级事件增量索引）；
2. Node smoke：http-transport / models / mobile-http / projection-worker（+Windows PowerShell 两个）；
3. 真实 Runtime smoke（需本机安装 Flowix DSH）：runtime-stdio / runtime-http / runtime-llm，宿主装配器 `test/runtime/host.mjs` 拉起真实 Cordis 宿主（LLM 模式从 `~/.dsh/settings.yaml` 与 Flowix 秘密库供给真实凭证，隔离 DSH_HOME、密钥不落日志）。

## 2. CI 质量门禁清单

| 检查 | 工具 | 要点 |
| --- | --- | --- |
| 类型 | `tsc --noEmit`（web job）+ `npm run build` 前置 tsc + dsh-appserver `npm run typecheck` | strict 全开 |
| 单测 | vitest（前端 + dsh-appserver）、cargo test --lib | — |
| Lint | `cargo clippy --workspace --all-targets` | 暂未 `-D warnings`（"先绿灯再收紧"） |
| 包管理器 | `check-package-manager.mjs` | npm==10.8.2、package-lock 存在、禁 pnpm 锁文件 |
| 层级边界 | `check-layer-boundaries.mjs` | 四条规则（见 [10-依赖关系全景](10-依赖关系全景.md) 第 4 节） |
| 前端债务 | `check-frontend-debt.mjs` | 棘轮式（ratchet）结构债务检查 |
| Bundle 预算 | `check-web-bundle.mjs` | 桌面启动图：JS ≤3MB raw / 900KB gzip；禁 Shiki 语法包入启动图；mermaid/shiki/katex 不得 modulepreload；入口 JS ≤700KB、CSS ≤500KB；Inter 字体 ≤12 个且全 woff2（沿 Vite manifest 递归静态 import 计算） |
| DSH 打包 | `dsh-native-deps.test.mjs` | 原生依赖选择 + `.node` 二进制头部不变量 |

## 3. 构建期不变量（脚本内建断言）

- 版本三方一致（package.json / Cargo.toml / tauri.conf.json），dev 与 build 启动即断言；
- 生产构建必须产出**新鲜**的更新器产物（`.dmg/.app.tar.gz/.sig` 等），"Tauri 成功但无产物"直接失败；
- DSH：koffi 可选依赖精确版本、`.node` 实际架构、entitlements 非 jitless 启动验证、从最终 tar.gz 回放冒烟；
- 更新器发布：manifest 经 `verify-updater-release.mjs` 校验、产物先传不可变前缀再指 latest。

## 4. 测试命令速查

```bash
npm test                      # 前端全部单测
npm run test:rust             # Rust workspace lib 测试
cargo test --manifest-path app/Cargo.toml --workspace            # 含集成测试（本地全量）
cd dsh-appserver && npm test  # DSH 应用服务器
npm run test:dsh:packaging    # DSH 打包不变量
npm run check:layers          # 前端层级
npm run build                 # tsc + vite build + bundle 预算
```
